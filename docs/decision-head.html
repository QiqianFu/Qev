02

为什么取末尾 token？先看读出标记从哪里来

2.1 标记从输入时就存在，表示在各层中逐步更新

“第 31 层把一段文字融合成一个新 token”容易造成误解。实际做法是：编码输入时，就在问题末尾放一个专用读出标记，在每个候选末尾放一个结束标记。它们和其他 token 一起进入主干；最终取这些固定位置的隐藏向量，分别作为问题和候选的表示。

问题前缀： [state ...] [question ...] <|fim_suffix|> ← 问题读出位置 候选 1 路径：[state ...] [question ...] <|fim_suffix|> [<|box_start|> 候选 1 文本 ...] <|box_end|> 候选 2 路径：[state ...] [question ...] <|fim_suffix|> [<|box_start|> 候选 2 文本 ...] <|box_end|> 候选 3 路径：[state ...] [question ...] <|fim_suffix|> [<|box_start|> 候选 3 文本 ...] <|box_end|>

这里按根到叶的逻辑路径展开。候选 1/2/3 的 <|box_end|> 使用相同 token ID，但所在分支的前文不同，经过主干后得到的隐藏向量也不同。读出的是上下文化后的隐藏向量，不是该标记固定不变的 embedding。

为什么选段末？因果结构让这个位置能够利用完整前文。

A → B → C → <结束标记> A 的位置：没有后面的 B、C 信息 B 的位置：没有后面的 C 信息 结束标记：在因果计算图中可以依赖 A、B、C 的全部内容

问题末标记可以利用完整的 state + question；候选末标记可以利用完整的 state + question + 当前候选。把专用标记放在段末，就给每段提供了一个可读完整本分支、且位置明确的固定维度接口。这是一种设计选择；也可另行设计均值池化或池化网络，并非 attention 只能取最后一个位置。

它为何能承担“摘要”？由任务训练推动，不由标记名字保证。

决策头依靠这些位置的向量打分，训练损失沿这条路径反向传播，推动可训练参数把对决策有用的信息保留在读出表示中。标记不是天然的总结器，也不保证无损保存整段文字。进入第 31 层前，这些位置已经积累了前面各层的信息；最后一层继续更新它们。

取一个位置的输出，不等于只让这一个位置提供信息。第 31 层中，候选结束标记产生 query，去读取许多位置的 K/V；最终只留下这个 query 对应的输出向量。其他候选既可以通过末标记提供上下文摘要，也可以通过中间 token 提供细粒度信息。

输入标记见 encoding.py 的 SPECIAL、Encoder.candidate_tokens 与 Encoder.__call__；段末下标见 tree.py 的 TreeLayout._build，最终读出见 joint_readouts。

“并行”具体发生在哪些维度？

当前 9B 是混合主干：24 层 Gated DeltaNet + 8 层 full attention。下面展示实际逐层执行，而不是把三条候选路径笼统叫作一个 batch。

32 个 DECODER 层 / 层号从 0 开始
L = Gated DeltaNetA = 普通 full attentionJ = 第 31 层 joint readouts

3.1 唯一 token 合并：先把大矩阵乘法做满

_execute_tree 把一个 microbatch 的记录构成 forest，隐藏状态为 H ∈ [1,N_total,4096]，其中每条记录的 state 只存一份，每题 question 只存一份。对同一层，投影与 MLP 处理全部唯一 token；不先分别对 C₁、C₂、C₃ 调三次完整主干。

参考 leaf rows： [S Q C₁], [S Q C₂], [S Q C₃] 实际长度： 8 9 8 → 25 token-work（padding 后 27） 树形 packed： [S Q C₁ C₂ C₃] → 15 unique tokens 前缀共享减少： 25 − 15 = 10 个重复 token → 本例投影 / MLP token-work 减少 40%

上述 40% 是符号示例的线性层 token 工作量变化，不是端到端实测加速比例。普通 attention 的稠密计算形状、分组 padding、kernel 调度和显存读写仍有各自开销。

卷积历史来自祖先路径

每个节点 gather 自己父路径末端的历史，拼上本节点的投影 token 后做 causal depthwise conv。C₂ 的历史来自 S+Q，不来自物理上前一段 C₁ 的尾部。配置卷积 kernel=4；代码 gather 最多 4 个祖先 token，再只保留当前节点输出。

状态分叉保持梯度

initial = cat(states[parent] for child in group)。同一父状态可出现多次，autograd 将各子分支的梯度加回父状态。训练走可对 initial/final state 求导的 chunk kernel，没有将父状态 detach 成推理缓存。

每个 value head 的简化递推（q/k 已归一化，忽略具体 kernel 排布）： F̄ₜ = exp(dₜ) · Fₜ₋₁ δₜ = βₜ · (vₜ − kₜᵀ F̄ₜ) Fₜ = F̄ₜ + kₜ δₜᵀ # F ∈ ℝ^[128,128] yₜ = qₜᵀ Fₜ # q 包含 1/√128 缩放 F_C₁,0 = F_C₂,0 = F_C₃,0 = F_parent # 相同初值，之后各自演化

9B DeltaNet 有 16 个 key heads、32 个 value heads，key/value head dim 都为 128。Q/K 在需要时按 value heads 重复。上述公式表达因果语义；训练用 chunk 算法并行化段内计算，Python 并不逐 token 循环。分组 padding 位置将 β 和 log-decay 设为 0，使状态转移为恒等，父节点的 final state 不被 padding 推进。

多题记录的依赖深度：S → {Q₁,Q₂,…} → {各题候选}。同一深度可跨记录、跨题合批；分组受到 rows_per_forward 与 max_padded_tokens 限制。单题合并 S+Q 后只有两级。多组之间会循环调用 kernel，所以“一次逐层前向”不等于所有分支只有一次 GPU kernel launch。

04

最后一层：候选 token 怎样读取彼此？

第 31 层是 full attention。当前路径在这一层将 query 数量从 N 缩减到 R，只计算最终会被读取的位置；K/V 仍覆盖全部唯一 token。

先沿候选 1 的结束标记，走完这一层

输入是 C₁* 在前面各层中已经形成的表示。own/cross 各自返回一个对 V 加权汇总后的内容向量，随后更新 C₁* 的表示。下面四步说明“两个 attention 加起来以后，发生什么”。

01 / 读取并混合两路提供更新内容

own 读取 S+Q+C₁；cross 读取 C₂/C₃ 的全部 token。cross 乘可学习的强度系数，再加到 own 上。

02 / 写回整理更新量，加回旧表示

各 head 结果拼接后，经过原生输出门与 o_proj；将得到的更新量加回 C₁* 原来的向量。这是第一次残差。

03 / 加工MLP 加工，再做残差

对中间表示做归一化和 MLP，将加工结果再加回中间表示。MLP 只加工当前向量，不再读取其他 token。

04 / 读出最终归一化，得到 e₁

将这一个位置的最终向量交给集合头。C₂*、C₃* 同时得到 e₂、e₃；问题标记只走 own，得到 h_q。

混合信息 = own 结果 + cross 强度 × cross 结果 更新量 = 输出投影(原生输出门 × 混合信息) 中间表示 = C₁* 原来的向量 + 更新量 加工结果 = MLP(归一化(中间表示)) e₁ = 最终归一化(中间表示 + 加工结果)

这里省略多头拆分与拼接。第 31 层交出的是 h_q、e₁、e₂、e₃ 四个向量；后面的集合决策头才负责候选比较、打分与概率输出。读出位置的来源见第 2.1 节。

4.1 两张 attention map，共用一份 QKᵀ

令 X = RMSNorm(H³¹_input)，reads=[Q*,C₁*,C₂*,C₃*]。所有候选的 K/V 都由进入第 31 层之前的残差流生成。一次性计算 readout Q 与所有 K 的 score，随后用两个不同的 mask 各自归一化。

M_own：保持各自原因果路径

query \ keySQC₁C₂C₃
Q*全全———
C₁*全全全——
C₂*全全—全—
C₃*全全——全

读出恰在各自段末，因此 own 的本段因果前缀就是整段。

M_cross：只允许同题其他候选 span

query \ keySQC₁C₂C₃
Q*—————
C₁*———全全
C₂*——全—全
C₃*——全全—

“全”包含候选开/闭边界 token。C₁* 可看逻辑 position=8 的 C₂*，cross 不再施加本分支的因果截断。

Sₕ = Qₕ Kₕᵀ / √256 # [R,N]，对 16 heads 同时计算 A_own,h = softmax_key(Sₕ + M_own) A_cross,h = softmax_key(Sₕ + M_cross) # 每行在所有兄弟 token 上合并归一化 O_own,h = A_own,h Vₕ O_cross,h = A_cross,h Vₕ Mₕ = O_own,h + αₕ O_cross,h, αₕ = tanh(gₕ)

cross 并不是“每个兄弟各做一次 softmax 然后平均”。对 C₁*，分母同时包含 C₂ 的 4 个 token 与 C₃ 的 3 个 token；两个候选不被强制分配相同概率质量。候选长度、每个 token 的 key 和 query 匹配程度都会影响 cross 质量分配。

两个门控的含义完全不同

gₕ 是新加入的 16 个静态可学习标量，每个主干 query head 一个，对该层的所有 readouts 共用；初始化为 0，tanh 范围为 (−1,1)。gate 是原 Qwen attention 的输入相关输出门，由 q_proj 同时产生，形状 [R,16,256]，在混合后取 sigmoid。

这不是一张归一化概率矩阵

可将混合写成 (A_own + αA_cross)V，但对有兄弟候选的行，系数和为 1+α；α 可为负。因此组合图只是两路加权 support，不能解释为第三次 softmax 或标准 attention probability。g=0 关闭本层 cross，集合头仍然会交互。

4.2 C₁ 与 C₂ 同时交互，不互相等待最终输出

e₁ = FinalLayerRead(H_C₁*^in ; KV_S,Q,C₁^in ; KV_C₂,C₃^in) e₂ = FinalLayerRead(H_C₂*^in ; KV_S,Q,C₂^in ; KV_C₁,C₃^in) e₃ = FinalLayerRead(H_C₃*^in ; KV_S,Q,C₃^in ; KV_C₁,C₂^in) ↑ 所有 K/V 都来自同一层输入 不存在：先算 e₁，再把 e₁ 当作 C₁ 的新 K/V 供 e₂ 读取

C₂ 的最后一个 token 在前 31 层已经汇总了 S+Q+C₂；因此 C₁* 读取它时可获得 C₂ 的语义摘要，同时还能读取 C₂ 中间 token 的局部信息。这是一次同步的 token-level 信息交换。之后集合头还会做两轮向量级交换。问题 readout 的 cross 整行为空，保留前缀语义。

flatten → 原生 gate → o_proj[R,4096][4,4096]
最终输出h_q:[D], E:[K,D][4096], [3,4096]
U = H[reads] + o_proj(ConcatHeads(M) ⊙ sigmoid(gate)) Y = FinalRMSNorm(U + MLP(PostAttentionRMSNorm(U))) h_q = Y[0] ; E = Y[1:K+1]

最终层只对 reads 做 q_proj、输出投影及 MLP；其他 token 仍提供 K/V，但不再计算无用的末层 query 输出。cross 无 key 的行（问题或 K=1）先安全处理全遮蔽，再把权重乘成零，避免 softmax(全 −∞) 的 NaN。

05

集合决策头：从 4 个向量到 3 个 logits

以 K=3 展开。这里的“token”已不再是自然语言 token，而是 1 个问题读出向量 + 3 个候选读出向量。

5.1 输入投影只沿通道计算，不在这一步交换候选信息

q = W_p LayerNorm₄₀₉₆(h_q) + b_p + r_q # [256] cᵢ = W_p LayerNorm₄₀₉₆(eᵢ) + b_p # [256] X⁰ = stack(q,c₁,c₂,c₃)[None] # [1,4,256] W_p ∈ ℝ^[256,4096], b_p ∈ ℝ^[256], r_q ∈ ℝ^[256]

self.norm 和 self.project 被 question/candidates 共用。LayerNorm 对每个向量的 4096 维做归一化，既不在 K 上做归一化，也不会把不同候选混起来。r_q 是可学习的问题角色向量，初始化为 0；候选没有独立角色参数或按 ID 查询的 embedding。

5.2 两层都是这张全连接 map

query \ keyqc₁c₂c₃
q✓✓✓✓
c₁✓✓✓✓
c₂✓✓✓✓
c₃✓✓✓✓

实际每层有 4 张学习到的 4×4 权重矩阵，对应 4 个 attention heads；两层的支持关系相同，权重参数与数值各自不同。

这一阶段 question 开始读候选

主干中的 h_q 始终只包含 S+Q。第一层集合 attention 后，q¹ 可以汇总 c₁/c₂/c₃；第二层中每个候选可再次读取这个集合相关的 q¹。

第一层的 c₁¹ 同时读取 q⁰、c₂⁰、c₃⁰；第二层读取的是更新后的 q¹、c₂¹、c₃¹。两轮更新都有残差，最终 q² 与 cᵢ² 一起进入 scorer。

头中没有 RoPE、绝对位置编码或 causal mask；它只处理当前题的 K+1 个向量。其 attention head dim=64，与主干 16 heads × 256 完全不同。

5.3 每层 Pre-Norm Transformer 的完整计算

for ℓ = 0,1: # 两套独立层参数 U = LN_attn,ℓ(Xℓ) # [1,4,256] Qₐ,Kₐ,Vₐ = split_heads(U WQ, U WK, U WV) # 各 [1,4 heads,4 positions,64] Aₐ = softmax_key(Qₐ Kₐᵀ / √64) # [1,4,4,4]，无 mask Attn = ConcatHeads(Aₐ Vₐ) WO # [1,4,256] Y = Xℓ + Attn Xℓ⁺¹ = Y + W₂ GELU(W₁ LN_ffn,ℓ(Y)+b₁)+b₂ # FFN 256→1024→256

上式为含 bias 的标准线性投影语义（Q/K/V/O 的 bias 在符号中省写），对应 nn.TransformerEncoderLayer(batch_first=True, norm_first=True, dropout=0.0, activation="gelu")。外面是 ModuleList，两层后没有额外的统一 encoder norm；下一步 scorer 自带 LayerNorm(512)。

5.4 Shared scorer：候选摘要与问题摘要拼接

q′ = X²[0,0] # [256] C′ = X²[0,1:] # [3,256] Uᵢ = concat(c′ᵢ, q′) # [512]，候选在前、问题在后 Z = Linear₂₅₆→₁(GELU(Linear₅₁₂→₂₅₆(LayerNorm₅₁₂(U)))) z = squeeze(Z) # [3]，每候选 1 个标量

scorer 是对 K 行一次性计算的共享函数。它不是一个固定输出 3/5/128 类的 Linear(256,K)，也不是与预定义类别 embedding 的 pointer dot product。K 只改变输入行数；None、true、false、任意等级都走同一个 Linear(256,1)。

因此“无候选序号 embedding”仍允许有选项集合效应。保持每个候选的 ID 与文本不变，仅重排列表，理想计算满足 f(S,Q,πC)=πf(S,Q,C)。但增删一个候选会改变主干 cross、集合 attention 和最终归一化，已有候选的 logits 与相对赔率都可以变化。多个完全相同候选还会增加注意力分母与 softmax 竞争，不具有重复项幂等性。

6.2 Noul 是两个动态候选的竞争
p_true = exp(z_true/T) / (exp(z_false/T)+exp(z_true/T))
       = sigmoid((z_true−z_false)/T)
p_false = 1−p_true
这是两类 softmax 的代数恒等式。实现中依然分别构造 false / true 候选，执行主干 cross、两层集合 attention、共享 MLP，得到两个 logits。它没有单独的布尔 sigmoid head，也没有三个互不相关的“置信度”神经元。


6.3 Score 输出分布，不直接回归一个实数
5 级 score 有 5 条独立候选分支，等级数字被编码进 level i: ... 文本。集合头没有专门的 ordinal positional embedding、累积阈值网络或单调性约束。模型可从文本与训练目标中学等级语义，但当前 CE 不显式惩罚“错三级”比“错一级”更重。
给定示意分布 p = [0.05, 0.10, 0.55, 0.20, 0.10]：
argmax(p) = level 2
E[level]  = Σᵢ i·pᵢ = 2.20
当前 predict_request 返回 prediction="2" 与 probabilities；不自动返回 2.20
如果需要连续评分或业务分值，应由调用方按明确的 level→value 映射求期望。通过 canonical schema 重排 score 候选时应保留 ID 与文本；直接重排 typed API 的 criteria 列表会重新编号，已经改变等级语义。


6.4 Choice 的 None 与多标签语义
None 是普通候选，拥有自己的文本、分支、eᵢ、logit 和 softmax 竞争。当前 as-provided 推理不自动插入；训练时的 None 插入是数据增强。K 增加时两级交互矩阵随之增大。这里的 choice 是一次候选分布决策；需要多个可同时为真的判断时，应定义多个 noul 问题，而不是把一次 softmax 当作多标签独立 sigmoid。






07
梯度怎样穿过共享前缀与两级交互？


7.1 先按题、再按记录平均
L_q = −Σᵢ y_q,i · log softmax(z_q)ᵢ
L_r = (1 / J_r) Σ_q∈r L_q
L_batch = (1 / B) Σ_r L_r                     # B 为该步的记录数口径
∂L_q/∂z_q,i = p_q,i − y_q,i
硬标签转换成 one-hot；软标签直接监督分布。一次题内的 K 个候选构成同一个 softmax 和同一个 loss，不是 K 个独立二分类训练样本。候选数更多不会通过“多几个 leaf rows”自动获得更大的记录权重。训练 CE 使用原始 logits，即 T=1；推理 model.temperature 单独做 z/T。


7.2 树分叉的反向传播是汇合
前向：F_parent ─┬→ C₁ ─┐
                ├→ C₂ ─┼→ joint readouts → SetHead → L_q
                └→ C₃ ─┘
反向：∂L/∂F_parent = Σᵢ (∂L/∂F_Cᵢ,0)         # 所有引用同一父状态的分支累加
token-level cross 使 C₁ 的 loss 路径也能通过 C₂/C₃ 的 K/V 回传；集合 attention 再建立题内各 eᵢ 之间的梯度联系。共享 S 与 Q 的表示只算一份，不意味着梯度只接受某一个候选的贡献。训练路径不把中间状态作为 detached 推理 cache。
初始化 g=0 时，末层 cross 对候选向量的直接贡献为零；但 d tanh(g)/dg|₀=1，所以 gate 仍可获得梯度。此时集合头照常交互。是否更新主干权重由全参 / LoRA / head-only 训练设置决定，不改变这里的前向语义。


7.3 当前与可选序数 loss 分开看
可选 RPS（仅 score，按整数 candidate ID 排序）：
L_q += ord_w / (K−1) · Σ_{k=1}^{K−1}(CDF_p(k)−CDF_y(k))²
可选 HL-Gauss：在等级 rank 上平滑 target，再做交叉熵
当前展示的 fullft_4gpu_lrdecay09 配置没有设置 ord_w 或 score_hl_sigma，默认都是 0。因而不能把“项目代码支持 RPS”写成“当前 score 头已带序数 loss”。RPS 按 ID 的数值顺序计算 CDF，HL-Gauss 使用排序后的 rank 间距。


7.4 精度边界
位置当前规则原因 / 限定
主干投影 / MLP训练外层 BF16 autocast全参 FSDP 使用 FP32 主权重与 BF16 计算；这里没有声称整个 backbone 都是 FP32。
joint scores、softmax、加权求和fp32_einsum 显式关闭 autocast；输入转换 FP32降低 attention reduction 的数值敏感性；混合结果在原层输出投影前转回相应计算 dtype。
SetDecisionHead入口关闭 autocast，question/candidates 转 FP32LN、投影、两层 Transformer、scorer 均按此头的 FP32 策略执行。
CE / 概率读出FP32 logits 与 log_softmax / softmaxcheckpoint 可保存 temperature；默认 T=1 不代表已校准。






08
复杂度、可观测性与实现边界


8.1 节省了重复前缀，但并非所有 attention 都是稀疏计算
N_ref  = Σⱼ Σᵢ (|S| + |Qⱼ| + |Cⱼᵢ|)
N_tree = |S| + Σⱼ (|Qⱼ| + Σᵢ |Cⱼᵢ|)
R      = Σⱼ (Kⱼ+1)
计算段主要工作 / attention 形状不能据此推断的事
前 31 层逐 token 投影 / MLP与 unique tokens N_tree 成正比的线性层工作；DeltaNet 状态按树调度。token-work 减少比例不直接等于墙钟加速。
普通 full-attention单记录有效形状 H·N_record²；多记录分桶 B·H·W²。mask 中的零可见块没有自动变成专用 block-sparse kernel。候选很长或很多时，N_tree² 可能超过各 leaf 方阵的平方和。
末层 joint attention当前源码显式计算 scores[H,R_total,N_total]，对 whole forest mask。普通 full-attention 避免跨记录大方阵，不等于 joint 已按记录分桶；joint 仍有被 mask 掉的跨记录矩形计算。
每题集合头投影 O((K+1)·D·d)；每层 attention O((K+1)²·d)，线性层/FFN O((K+1)·d²)。头参数不随 K 变，但计算与内存随 K 变；当前也没有跨题 padded set batch。


8.2 推理有多条执行路径，图中以 tree-batched 训练语义为中心
leaf-rows/reference 重复前缀，为对照路径；cached 推理用 state→question→candidate 的两级 cache 分叉；tree/tree-batched 按层对唯一 token 执行。它们意在保持同一计算图的输出语义，具体数值容差与 BF16 差异需要按路径验证。普通 attention 的 mask 不能单独隔离 DeltaNet，任何路径都必须同时隔离 recurrent state 与 convolution history。


8.3 如果要采集“真实 attention 权重”
本页的彩色矩阵是 support。对于指定 checkpoint 与请求，实际数值应在对应计算位置采集，并带上层号、head、query/key token、ID 和逻辑位置一起解释：
  • joint 层：在 joint_readouts 的 scores 之后分别保留 own/cross softmax，及 tanh(model.joint_gate)。问题行和无兄弟行的 cross 必须按源码清零。不要把两路相加后的系数称作归一化 attention。
  • 集合头：用相同的 pre-norm 输入和 MHA 参数，在分析副本中设置 need_weights=True, average_attn_weights=False，得到每层 [1,4,K+1,K+1]。当前 TransformerEncoderLayer forward 并不返回这些权重；不能只 hook 模块输出就假定拿到了 A。
  • 普通 full-attention：当前 SDPA 通常不会返回完整权重，可在分析副本中读取归一化且 RoPE 后的 Q/K，结合同一树 mask 重建 softmax，或使用匹配的 eager 路径。切换 kernel 后应核对输出差异。
  • DeltaNet：不存在等同普通 softmax attention 的 N×N 权重输出。可以分析状态转移、门控或等价影响系数，但应使用不同的图注，不能将本页树 mask 当作其实际数值权重。
真实权重只能说明这一输入、这一层与 head 下的信息聚合；其大小本身不等价于对最终预测的因果贡献。若要分析候选的影响，还可做候选替换、门控消融或梯度 / 干预对照。
